### 后端接口与鉴权

- 统一前缀 `/api`，统一响应体 `{ code, message, data }`（code=0 成功）
- 鉴权：JWT 双 token（access 2h / refresh 7d）；`SecurityConfig`：`/api/auth/**` 与 `/actuator/**` permitAll、`/api/user/**` hasAnyRole(USER/ADMIN/AGENT)、`/api/admin/**` hasRole(ADMIN)、`/api/agent/**` AGENT 占位、其余 denyAll
- 身份一律取 `auth.UserContext`（ThreadLocal，JWT 过滤器写入）；接口不接受 userId 入参（越权防线）
- 401 → HTTP 401 + JSON 40101；业务错误 → HTTP 200 + 语义码（40001/40901/40902/42901/50002）
- 钱包接口：GET /api/user/wallet、GET /api/user/wallet/transactions?cursor=&limit=、POST /api/user/wallet/recharge（1~1000 元）；资料接口：GET/PUT /api/user/profile

### 6.3 关键决策

- **sse.ts 缺口（本批修正核心）**：业务错误为 HTTP 200 + `{code,message}` 信封（GlobalExceptionHandler），sse.ts 现只处理 `!resp.ok`——40902/42901/50002 会被静默吞掉（流内无 `data:` 行，静默结束）。修法：读流前检查 Content-Type，application/json 则抛 onError（42901/50002 → retryable=true）。
- 历史消息后端按 id 倒序游标分页（ChatSessionService.messages 已核实），前端**反转正序**渲染，加载更多用 nextCursor。
- 发送时序：乐观插入用户气泡 + AI 占位（streaming）→ delta 拼接 → done 回填 messageId；流式期间禁发送（防 42901）。
- 停止生成：store 持 AbortController，AbortError 静默，部分内容保留。
- 错误气泡 + 重试按钮（仅 retryable=true）；已知妥协：后端无 requestId 幂等，重试可致 user 消息重复落库（M2 改进项）。
- 7 工具文案映射放 api/chat.ts：queryMyOrders / queryEstimatedTime / queryRefundProgress / queryPoints / queryCoupons / recommendDrinks / queryStores（源自 ai/tool 四工具类 @Tool 方法名，已清点）。
- 无 activeSession 时首条消息先 POST create；欢迎语纯前端不落库；widget 开合状态入 store（移动端面板可见性 = `route.name === 'chat'`，PC = store.open）。
