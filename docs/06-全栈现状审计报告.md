## 4. 登录接口的 userInfo 是否包含 role

- **包含。** `backend/src/main/java/com/zmh/atlantic/coffee/auth/dto/AuthDtos.java:32`：

```java
public record UserInfo(Long userId, String phone, String nickname, String role, Integer memberLevel)
```

- `role` 取值为 `USER/ADMIN/AGENT`（user 表同名字段）；`memberLevel`（TINYINT 1/2/3）也一并返回，等级名（L1 航海员/L2 领航员/L3 船长）由前端映射。
- 注意：前端目前**没有任何 api 层消费该结构**（无 axios/fetch 封装、无 pinia store），登录态尚未接入页面。

## 7. SecurityConfig 中 /api/admin/** 的权限规则

- **文件**：`backend/src/main/java/com/zmh/atlantic/coffee/auth/SecurityConfig.java`（行 68）：

```java
.requestMatchers("/api/admin/**").hasRole("ADMIN")
```

- 配套机制：`JwtAuthenticationFilter` 解析 access token 后写入 `ROLE_` 前缀权限（含 ASYNC dispatch 参与与 saveContext 持久化，决策 #65）；未认证 → 401 JSON（40101），已认证但无 ADMIN 角色 → 403 JSON（40301）。
- 同文件相邻规则：`/api/auth/**` permitAll、`/actuator/**` permitAll、`/api/agent/**` hasRole("AGENT")（M3 占位）、`/api/user/**` hasAnyRole(USER/ADMIN/AGENT)、其余 `denyAll()`。
- **现状**：`/api/admin/**` 下无任何 Controller（知识库后台接口属 M2 范围，未建）。
