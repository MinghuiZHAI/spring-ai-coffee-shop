## 0. 设计基线与补充标注

- 本文档严格对齐 PRD v1.2（意图分类/只读边界/状态机/枚举预留）、技术栈 v1.2（Spring AI Alibaba 1.1.2.0/MyBatis-Plus/SseEmitter/Redis 8）、总体设计 v1.3（双层路由/IntentAgent/SSE 六事件/close 幂等）。
- 总体设计未覆盖、由本文档补充的细节以 **【补充】** 标注，共 7 处：① orders 表名（`order` 为 MySQL 保留字）；② 订单状态模拟推进器与"确认取餐"按钮（MVP 无门店端）；③ 退款到账两跳节奏（T+30s 已通过 / T+60s 已到账）；④ ChatClient bean 粒度（单 ChatModel 多 ChatClient + 调用级 options 换模型）；⑤ KB 种子向量索引启动构建（KbBootstrapRunner）；⑥ 购物车同规格合并与会话标题生成策略；⑦ kb_type 过滤字段经自定义 RedisVectorStore bean 显式声明（TAG 类型）——starter 属性方式不支持（§3.1.1）。
- 代码与配置为可直接粘贴的实现基线；Spring AI 接口签名以 spring-ai 1.1.2 实际为准（个别方法名可能随版本微调，不改变设计结构）。

## 1. 数据库详细设计

### 1.1 通用约定与 Flyway 规划

- 全表 InnoDB、utf8mb4 / utf8mb4_0900_ai_ci；主键 id BIGINT UNSIGNED AUTO_INCREMENT；统一 created_at / updated_at（DB 默认值 + MyBatis-Plus 自动填充双保险）。
- 逻辑删除仅用于内容型表（user/product/category/store/coupon_template/kb_document），字段名 `deleted`，由 MyBatis-Plus 全局配置接管；交易与日志表不做逻辑删除。
- **【补充】`order` 为 MySQL 保留字，订单表命名 `orders`**，实体类仍为 Order（@TableName("orders")）。
- 脚本规划：`V1__init.sql`（18 张表全部 DDL 与索引）、`V2__seed_data.sql`（演示账号、5 分类 + 25 SKU、6 门店、2 活动 + 3 券模板、会员规则/FAQ/品牌/菜单知识库文档）、`V3__` 起按后续演进顺延（如 `V3__add_kb_sub_type.sql`）。种子知识库文档 status=PUBLISHED，其向量索引由启动构建器生成（§1.4）。

### 1.4 【补充】KB 种子向量索引启动构建

V2 种子中的 PUBLISHED 文档在应用首次启动时还没有向量索引。新增 `KbBootstrapRunner`：实现 `ApplicationListener<ApplicationReadyEvent>`，在应用就绪事件后检查 Redis 向量索引是否为空，为空则调用 KbIndexService 对全部 PUBLISHED 文档执行一次全量重建（复用总体设计 §3.4 管道）。演示环境"一键起库即有可用的 RAG"由此保证。

> **启动顺序保证**：监听 ApplicationReadyEvent 而非实现 ApplicationRunner，是因为 ReadyEvent 触发时 Spring 上下文已全部初始化——VectorStore bean（含 §3.1.1 的自动 FT.CREATE）已完成索引创建，避免在索引尚未建好时把"索引不可用"误判为"索引为空"而提前触发重建。

```java
    OrderStatus(String label) { this.label = label; }
    public String label() { return label; }
}
```

| 当前状态 \ 操作 | PAY 支付 | START_MAKING 开始制作 | FINISH_MAKING 制作完成 | PICKUP 取餐核销 | CANCEL 取消 | APPLY_REFUND 申请退款 | REFUND_SUCCESS 退款到账 |
|---|---|---|---|---|---|---|---|
| PENDING_PAYMENT | PAID_TODO | ❌ | ❌ | ❌ | CANCELLED | ❌ | ❌ |
| PAID_TODO | ❌ | MAKING | ❌ | ❌ | CANCELLED（自动建全额退款单） | ❌ | ❌ |
| MAKING | ❌ | ❌ | READY | ❌ | ❌（转人工沟通） | ❌ | ❌ |
| READY | ❌ | ❌ | ❌ | COMPLETED | ❌ | ❌ | ❌ |
| COMPLETED | ❌ | ❌ | ❌ | ❌ | ❌ | REFUNDING（限 24h 内） | ❌ |
| REFUNDING | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ | REFUNDED |
| CANCELLED / REFUNDED | 终态，无转换 | | | | | | |

> 【补充】MVP 无门店端，PAID_TODO→MAKING→READY 由**订单状态模拟推进器**驱动（§2.4）；READY→COMPLETED 由用户端"确认取餐"按钮核销（不做取餐码强校验）。PRD 3.4 文字"6 个状态"与状态图 8 节点的关系：6 主状态 + 退款流转 2 态，本文按图的全量 8 值实现。

```java
// 唯一的状态流转入口（除模拟推进器与退款扫描的批量路径外，所有流转必须走这里）
public Order transit(Long orderId, OrderAction action) {
    Order order = orderMapper.selectById(orderId);
    if (order == null) throw new BizException(40401, "订单不存在");
    if (!order.getStatus().can(action)) {                       // 第一层：Java 侧转换表校验
        throw new BizException(40901, "当前订单状态不允许该操作：" + order.getStatus().label());
    }
    OrderStatus target = order.getStatus().next(action);
    order.setStatus(target);
    if (action == OrderAction.PAY)    { order.setPaidAt(now()); order.setPickupCode(genCode()); order.setExpectedFinishTime(now().plusMinutes(5)); }
    if (action == OrderAction.PICKUP) { order.setCompletedAt(now()); }
    int rows = orderMapper.updateById(order);                   // 第二层：UPDATE ... WHERE id=? AND version=?
    if (rows == 0) {                                            // 并发竞争失败
        throw new BizException(40901, "订单状态已被其他操作变更，请刷新后重试");
    }
    // 动作后置钩子
    if (action == OrderAction.PAY) pointService.earn(order);    // 下单得积分（实付 1 元 = 10 分）
    if (action == OrderAction.CANCEL && order.getStatus() == OrderStatus.CANCELLED && order.getPaidAt() != null) {
        refundService.createFullRefund(order);                  // 待制作取消 → 自动全额退款单（APPLYING）
    }
    return order;
}
```

> 两层防护语义：转换表负责"业务上非法"，@Version 负责"并发上过期"；二者任一拒绝即流转失败。REJECTED 退款态与 DELIVERY 取餐方式为预留值，MVP 不产生。

### 2.3 退款延迟到账（@Scheduled 两跳）

【补充】节奏细化：T+30s 申请中→已通过；T+60s 已通过→已到账。两跳而非单跳，是为了让"退款进度查询"工具在演示中能观察到中间态。

```java
@Component
@RequiredArgsConstructor
public class RefundScheduler {
    private final RefundMapper refundMapper;

    @Scheduled(fixedDelay = 5000)   // 每 5s 扫描；表即队列，条件更新天然幂等，重启自动续跑
    public void advanceRefunds() {
        LocalDateTime now = LocalDateTime.now();
        refundMapper.approveDue(now.minusSeconds(30));   // 申请中 → 已通过
        refundMapper.successDue(now.minusSeconds(60));   // 已通过 → 已到账
    }
}

@Mapper
public interface RefundMapper {
    @Update("UPDATE refund SET status = 'APPROVED', updated_at = NOW() " +
            "WHERE status = 'APPLYING' AND apply_at <= #{deadline}")
    int approveDue(@Param("deadline") LocalDateTime deadline);

    @Update("UPDATE refund SET status = 'SUCCESS', finished_at = NOW(), updated_at = NOW() " +
            "WHERE status = 'APPROVED' AND apply_at <= #{deadline}")
    int successDue(@Param("deadline") LocalDateTime deadline);
}
```

### 3.1 ChatClient bean 结构【补充】

单 ChatModel（starter 自动配置的 DashScopeChatModel）+ 5 个 ChatClient bean；模型档位用调用级 options **局部覆盖，未指定字段沿用 bean 级默认配置**，不建两个 ChatModel bean。

```java
@Configuration
public class AiClientConfig {

    @Bean  // IntentAgent：无记忆无 RAG 无工具，仅结构化输出
    ChatClient intentAgentClient(ChatModel chatModel) {
        return ChatClient.builder(chatModel)
                .defaultSystem(Prompts.INTENT_CLASSIFIER_PROMPT)
                .build();
    }

    @Bean  // 业务 Agent 装配模板：Prompt + 记忆 → RAG → 日志，工具按 Agent 专属注册
    ChatClient orderAgentClient(ChatModel chatModel, ChatMemory chatMemory, VectorStore vectorStore) {
        return ChatClient.builder(chatModel)
                .defaultSystem(Prompts.ORDER_AGENT_PROMPT)
                .defaultTools(new OrderTools())          // 只挂本 Agent 的工具
                .defaultAdvisors(
                    MessageChatMemoryAdvisor.builder(chatMemory).build(),            // ① 记忆
                    QuestionAnswerAdvisor.builder(vectorStore)                        // ② RAG
                        .searchRequest(SearchRequest.builder()
                            .topK(5).similarityThreshold(0.5f)
                            .filterExpression("kb_type == 'FAQ'").build())            // OrderAgent=FAQ 全量（总体设计 §4.1）；
                                                                                      // kb_type 过滤依赖索引中显式声明的 TAG 字段（§3.1.1），未声明时过滤静默失效
                        .build(),
                    new AiTraceAdvisor())                                             // ③ 日志（ai.log）
                .build();
    }
    // couponAgentClient（filterExpression: kb_type in ('MEMBER_RULE','ACTIVITY')，工具 MemberTools）
    // recommendAgentClient（kb_type == 'MENU'，工具 RecommendTools）
    // faqAgentClient（无 filterExpression 全库，工具 StoreTools）——四个 bean 同构，差异仅上三点
}
```

Advisor 顺序约定：**记忆最先**（组装历史消息）→ **RAG 其次**（对当前 query 检索并注入上下文）→ **日志最后**（最外层记录最终 prompt 与响应耗时）。各 Advisor 显式设置 order（20/30/40），避免依赖隐式注册顺序。

### 3.1.1 VectorStore bean 与 kb_type 元数据声明【补充】

Spring AI 官方要求：所有参与 FilterExpression 过滤的元数据字段必须在索引 Schema 中**显式声明**（MetadataField.tag / numeric / text），否则过滤条件**静默失效**——检索仍返回结果但不做字段裁剪。而 RedisVectorStore 的 starter 自动配置**不支持经属性声明 metadata 字段**（`spring.ai.vectorstore.redis.metadata-fields` 属性缺失为 spring-ai 已知问题，GitHub 有 issue 记录），因此放弃属性方式，改用自定义 bean：

```java
@Configuration
public class VectorStoreConfig {

    /** 显式声明 kb_type 为 TAG 字段；initializeSchema=true 时自动 FT.CREATE，索引 Schema 含该字段 */
    @Bean
    public RedisVectorStore vectorStore(JedisPooled jedis, EmbeddingModel embeddingModel) {
        return RedisVectorStore.builder(jedis, embeddingModel)
                .indexName("atlantic-kb")
                .prefix("atlantic:kb:")
                .initializeSchema(true)
                .addMetadataFields(RedisVectorStore.MetadataField.tag("kb_type"))  // 方法名以 1.1.2 实际为准
                .build();
    }
}
```

- 该 bean 存在后自动配置退避，§6.1 中 vectorstore 配置块仅保留连接参数（index-name/prefix/initialize-schema 已移入 bean）。
- 等价备选：初始化后手动 `redis-cli FT.CREATE atlantic-kb ... TAG kb_type SEPARATOR |`；bean 方式优于手动脚本——随应用部署幂等生效，无需独立运维步骤。
- 部署核验：`redis-cli FT.INFO atlantic-kb` 确认 attributes 中存在 kb_type（TAG 类型），呼应技术栈 #13 的核验要求。

### 3.4 ChatMemory 自定义仓储

自定义 ChatMemoryRepository（MySQL 权威 + Redis 热缓存，技术栈 #15），配合内置 MessageWindowChatMemory(maxMessages=20)：

```java
public class MySqlRedisChatMemoryRepository implements ChatMemoryRepository {

    @Override
    public List<Message> findByConversationId(String conversationId) {   // conversationId = chat_session.id
        String key = "chat:memory:" + conversationId;
        List<String> cached = redis.opsForList().range(key, 0, 19);      // 最近 20 条
        if (cached != null && !cached.isEmpty()) {
            return cached.stream().map(MessageCodec::fromJson).toList(); // role 四值映射 USER/AI/AGENT/SYSTEM
        }
        List<ChatMessage> rows = chatMessageMapper.findLatest(conversationId, 20); // 游标倒查
        List<Message> messages = rows.stream().map(MessageCodec::toSpringMessage).toList();
        if (!messages.isEmpty()) {
            redis.opsForList().rightPushAll(key, messages.stream().map(MessageCodec::toJson).toList());
            redis.expire(key, Duration.ofHours(24));                     // 回填缓存
        }
        return messages;
    }

    @Override
    public void saveAll(String conversationId, List<Message> messages) { // 新消息持久化 + 缓存穿透写
        for (Message m : messages) {
            chatMessageMapper.insert(ChatMessage.of(conversationId, RoleMapper.toDb(m))); // USER/AI/AGENT/SYSTEM
            String key = "chat:memory:" + conversationId;
            redis.opsForList().leftPush(key, MessageCodec.toJson(m));
            redis.opsForList().trim(key, 0, 19);                         // LPUSH + LTRIM 截断
            redis.expire(key, Duration.ofHours(24));
        }
    }

    @Override
    public void deleteByConversationId(String conversationId) {          // 会话清理双删
        chatMessageMapper.deleteBySession(Long.valueOf(conversationId));
        redis.delete("chat:memory:" + conversationId);
    }
}

@Bean ChatMemory chatMemory(MySqlRedisChatMemoryRepository repo) {
    return MessageWindowChatMemory.builder().chatMemoryRepository(repo).maxMessages(20).build();
}
```

> role 映射：Spring AI 的 UserMessage→USER、AssistantMessage→AI；AGENT/SYSTEM 值域在 codec 中完整支持（M3 无需改存储层）。

> 相对总体设计 v0 草稿的变更：补入可执行的业务规则细节（状态机/24h 窗口/两跳到账/券四要素/输出格式条款），职责边界条款与 v0 逐字一致。终稿进入 Prompts 常量类，评测集回归后仅允许调"回答要求"段。

**INTENT_CLASSIFIER_PROMPT（IntentAgent）**

```text
你是 Atlantic Coffee 智能客服的意图分类器。你的唯一任务是把用户消息归类，不解答、不解释、不补充内容。

意图定义：
- ORDER：订单与售后——查订单/取餐码/预计完成时间/退款进度/退款规则/如何取消
- MEMBER：会员与权益——积分、优惠券、会员等级及相关规则
```

### 5.3 SSE 消费工具函数（src/utils/sse.ts）

```typescript
export interface ChatStreamHandlers {
  onIntent?: (e: { intent: string; confidence: number }) => void;
  onToolStart?: (e: { toolCallId: string; tool: string }) => void;
  onToolEnd?: (e: { toolCallId: string; tool: string; success: boolean; durationMs: number }) => void;
  onDelta?: (text: string) => void;
  onDone?: (e: { messageId: number }) => void;
  onError?: (e: { message: string; retryable: boolean }) => void;
}

/** fetch + ReadableStream 消费 SSE（技术栈 #28）：POST 可用、JWT 头可携带 */
export async function sendChatMessage(
  sessionId: number, content: string, token: string,
  h: ChatStreamHandlers, signal?: AbortSignal,
): Promise<void> {
  const resp = await fetch(`/api/user/chat/sessions/${sessionId}/messages`, {
    method: "POST",
    headers: { "Content-Type": "application/json", Authorization: `Bearer ${token}` },
    body: JSON.stringify({ content }),
    signal,
  });
  if (!resp.ok) {                                    // SSE 建立前的错误走 HTTP 状态码（总体设计 §5.5 边界）
    const message = await resp.text();
    h.onError?.({ message: message || `请求失败(${resp.status})`, retryable: resp.status >= 500 });
    return;
  }
  const reader = resp.body!.getReader();
  const decoder = new TextDecoder();
  let buffer = "";
  const openTools = new Map<string, string>();       // toolCallId → tool 名：并行调用按 id 配对

  for (;;) {
    const { done, value } = await reader.read();
    if (done) break;
    buffer += decoder.decode(value, { stream: true });
    const frames = buffer.split("\n\n");
    buffer = frames.pop()!;                          // 末帧可能不完整，留缓冲
    for (const frame of frames) {
      const dataLine = frame.split("\n").find((l) => l.startsWith("data:"));
      if (!dataLine) continue;
      const evt = JSON.parse(dataLine.slice(5).trim()); // 写法 A：一次 parse 拿全部信息
      switch (evt.type) {
        case "intent":     h.onIntent?.(evt); break;
        case "tool_start": openTools.set(evt.toolCallId, evt.tool); h.onToolStart?.(evt); break;
        case "tool_end":   openTools.delete(evt.toolCallId); h.onToolEnd?.(evt); break;
        case "delta":      h.onDelta?.(evt.content); break;
        case "done":       h.onDone?.(evt); return;
        case "error":      h.onError?.(evt); return;
      }
    }
  }
}
```

## 7. 决策记录（承接总体设计 #44 顺延）

| # | 决策 | 理由摘要 |
|---|------|----------|
| 45 | 订单表命名 orders（order 为 MySQL 保留字） | 反引号转义在全链路（DDL/MyBatis SQL/评测脚本）都是持续摩擦，改名一次成本最低 |
| 46 | 无门店端：订单状态由模拟推进器驱动（支付 30s→制作中，制作 3min→待取餐），READY→COMPLETED 由用户"确认取餐"核销 | 让 PRD 状态机全链路可演示；模拟推进用条件批量 UPDATE，幂等可重启；门店作业系统超出 MVP |
| 47 | 退款到账两跳节奏：T+30s 申请中→已通过，T+60s→已到账 | 单跳 30s 无中间态可查，"退款进度查询"工具失去演示价值；两跳仍在一分钟内，符合 PRD"约 30 秒"量级授权 |
| 48 | 单 ChatModel + 5 个 ChatClient bean，模型档位用调用级 options 局部覆盖（turbo/plus），未指定字段沿用 bean 级默认 | ChatClient 承载 Prompt+工具+Advisor 差异，ChatModel 只是传输；避免双 ChatModel bean 的配置分裂，切换模型 = 改 options 一行 |
| 49 | KB 种子向量索引由 KbBootstrapRunner 启动构建（监听 ApplicationReadyEvent） | "一键起库即有可用 RAG"（技术栈 #34 可演示性），避免 V2 种子与向量索引的时序耦合；ReadyEvent 时点保证 VectorStore 已初始化，不会误判空索引；空索引判断 + 全量重建复用既有管道 |
| 50 | uk_phone(phone, deleted) 联合唯一 | 逻辑删除表上单列唯一会阻止注销手机号重新注册；联合唯一是 MySQL 下的标准解法 |
| 51 | kb_type 过滤字段以自定义 RedisVectorStore bean 声明（MetadataField.tag），不走属性配置 | FilterExpression 过滤依赖索引 Schema 显式声明的元数据字段，未声明时**静默失效**；starter 自动配置不支持 metadata-fields 属性（spring-ai 已知问题），自定义 bean 是唯一可靠路径；FT.INFO 核验列入部署清单（v1.1） |
